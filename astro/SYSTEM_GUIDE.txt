================================================================================
  1. SYSTEM OVERVIEW
================================================================================

AstroTrace is a full-stack, real-time satellite orbit monitoring and anomaly
detection platform. It combines high-precision orbital mechanics with a
cinematic 3D Mission Control UI.

The core pipeline is:

  [CelesTrak TLE Data]
         |
         v
  [TLE Parser + Epoch Handler]
         |
         v
  [SGP4 Analytical Propagator]  <--- Actual "observed" state
         |
         v
  [RK4 Numerical Integrator]    <--- Predicted state (J2 + drag physics)
         | (Two-body + J2 + Drag)
         v
  [State Vector Comparison: Predicted vs. Actual]
         |
         v
  [Anomaly Engine: DeltaPosition, DeltaVelocity, RSW Decomposition]
         |
         v
  [Severity Classifier: NORMAL / WATCH / WARNING / CRITICAL]
         |
         v
  [FastAPI REST + WebSocket @ 2 Hz]
         |
         v
  [Three.js 3D Earth + Chart.js + HUD Telemetry + "What Happened?" Modal]

--------------------------------------------------------------
  4b. TLE FETCHER & PARSER  (backend/satellite/tle.py)
--------------------------------------------------------------

  Fetches Two-Line Element (TLE) sets from CelesTrak asynchronously via httpx.
  Parses TLE strings into structured fields:
    Name, NORAD ID, Classification, Epoch, BSTAR drag term,
    Inclination, RAAN, Eccentricity, Arg. of Perigee, Mean Anomaly, Mean Motion.
  Converts TLE epoch to Python datetime.
  Maintains local JSON cache (data/tle_cache.json) for offline operation.

  TLEManager class:
    get_tle(norad_id)  -> fetches from cache or CelesTrak
    refresh_all()      -> async background update of all satellites
    parse_epoch(tle)   -> returns datetime of TLE epoch

--------------------------------------------------------------
  4c. PHYSICS ENGINE  (backend/satellite/physics.py)
--------------------------------------------------------------

  RK4 Numerical Integrator
  -------------------------
  4th-order Runge-Kutta method integrates equations of motion.
  Given state [r, v] and time step h, computes 4 derivative evaluations
  (k1..k4) and combines with [1/6, 2/6, 2/6, 1/6] weights.

  Acceleration Model
  ------------------
  a_total = a_gravity_central + a_J2 + a_drag

  a_gravity_central (Earth point-mass gravity):
    a = -mu * r / |r|^3

  a_J2 (Oblate Earth Equatorial Bulge Perturbation):
    Accounts for Earth's equatorial bulge causing orbital plane precession.
    factor = (3/2) * J2 * mu * R_E^2 / |r|^5
    a_J2_x = factor * x * (5*z^2/|r|^2 - 1)
    a_J2_y = factor * y * (5*z^2/|r|^2 - 1)
    a_J2_z = factor * z * (5*z^2/|r|^2 - 3)

  a_drag (Atmospheric Drag):
    Exponential density model: rho(h) = rho_0 * exp(-h / H_scale)
    where h = |r| - R_E (altitude above Earth surface)
    F_drag = -0.5 * CD * A/m * rho * |v_rel|^2 in direction of v_rel
    v_rel = velocity relative to rotating atmosphere = v - omega_E x r

  Classical Orbital Elements Extraction:
    extract_coe(r, v) converts state vector to:
      a  -- semi-major axis (km)
      e  -- eccentricity
      i  -- inclination (deg)
      Omega -- RAAN (deg)
      omega -- argument of perigee (deg)
      nu -- true anomaly (deg)
      T  -- orbital period (minutes)
      eps -- specific orbital energy (km2/s2)
      h_apo / h_per -- apogee and perigee altitudes (km)

--------------------------------------------------------------
  4d. COORDINATE TRANSFORMS  (backend/satellite/coordinate.py)
--------------------------------------------------------------

  GMST (Greenwich Mean Sidereal Time)
    Converts UTC datetime -> GMST angle (radians) via IAU-76 formula.

  ECI -> ECEF
    ECI (Earth-Centred Inertial): axes fixed to distant stars.
    ECEF (Earth-Centred Earth-Fixed): rotates with Earth.
    Conversion: rotate ECI by -GMST around Z axis.

  ECEF -> Geodetic (WGS-84 Lat/Lon/Alt)
    Bowring's iterative method.
    Longitude = atan2(Y_ecef, X_ecef)
    Latitude  = iteratively solved from X, Y, Z and Earth's flattening.
    Altitude  = distance from surface along local normal.

  RSW / RIC Frame
    Satellite-centred frame rotating with orbital motion.
    R-hat = r/|r|                   (radial, away from Earth)
    W-hat = (r x v) / |r x v|      (cross-track, orbit normal)
    S-hat = W-hat x R-hat           (along-track / in-track)
    Used to decompose position error into its 3 components.

--------------------------------------------------------------
  4e. ORBITAL PROPAGATOR  (backend/satellite/propagator.py)
--------------------------------------------------------------

  SGP4 Propagator (Analytical)
    Uses python-sgp4 library. Accounts for J2, J3, J4, drag, lunar/solar
    gravity, solar radiation pressure. Called as satellite.sgp4(jd, fr).

  RK4 Propagator (Numerical)
    Integrates physics.py's force model forward in time from current SGP4 state.
    Produces the "predicted" trajectory for comparison with SGP4 "actual".

  Orbit Ribbon Generator
    Propagates for a full orbital period and returns ECEF, ECI, geodetic points.
    Frontend uses these to draw the cyan orbit line and purple ground track.

--------------------------------------------------------------
  4f. ANOMALY DETECTION ENGINE  (backend/satellite/anomaly.py)
--------------------------------------------------------------

  Deviation Calculation
    Every update:
      delta_r = |r_sgp4 - r_predicted|  (km)
      delta_v = |v_sgp4 - v_predicted|  (km/s)
    Decomposes delta_r into RSW components.

  Severity Classification (by delta_r):
    NORMAL:   < 1.0 km
    WATCH:    1.0 to 5.0 km
    WARNING:  5.0 to 20.0 km
    CRITICAL: >= 20.0 km

  Scenario Injector
    Perturbs the propagation reference state to simulate orbital events.

    Available scenarios:
      ORBIT_RAISE_MANEUVER      -> +delta_a (~30 km), +delta_v along-track
      ATMOSPHERIC_DRAG_SPIKE    -> -delta_a (~15 km), increased drag
      INCLINATION_PLANE_CHANGE  -> +/-delta_i (~0.3 deg), cross-track kick
      DEORBIT_BURN              -> -delta_a (~50 km), retrograde delta_v
      SENSOR_EPHEMERIS_UPDATE   -> random small noise on all elements
      RESET_NOMINAL             -> clears all perturbations

    After injection:
      * Deviation grows (often CRITICAL)
      * Red deviated orbit line appears on globe
      * "What Happened?" diagnostic modal shows probable causes

  "What Happened?" Diagnostic Engine
    Compares current Keplerian elements vs. baseline:
      delta_a, delta_e, delta_i, delta_alt, delta_v
    Assigns likelihood scores to candidate causes:
      Orbit Raise / Plane Change Manoeuvre
      Atmospheric Drag Spike
      Ephemeris Update / Sensor Reset
      Spontaneous Anomaly
    Outputs: status headline, assessment, recommendations, confidence %.

================================================================================
  8. FEATURE DEEP-DIVES
================================================================================

--------------------------------------------------------------
  8a. TWO-BODY + J2 + DRAG NUMERICAL PROPAGATION
--------------------------------------------------------------

  1. SGP4 gives initial state r0, v0 at current UTC time.
  2. RK4 integrator advances state using:
       dr/dt = v
       dv/dt = a_gravity + a_J2 + a_drag
  3. Each step: h = step_seconds (default 60 s).
  4. After N steps: trajectory of state vectors.

  The predicted trajectory is what the satellite SHOULD do physically.
  The SGP4 propagation is what the TLE SAYS it does.
  Difference = deviation worth investigating.

--------------------------------------------------------------
  8b. SGP4 ANALYTICAL PROPAGATION
--------------------------------------------------------------

  SGP4 (Simplified General Perturbations 4): NORAD standard algorithm.
  Accounts for: J2/J3/J4 oblateness, atmospheric drag (via BSTAR from TLE),
  lunar/solar gravity, solar radiation pressure.
  Python library: sgp4 by Brandon Rhodes.
  Call: satellite.sgp4(jd, fr) where jd+fr = Julian Date.

--------------------------------------------------------------
  8c. ANOMALY DETECTION & SEVERITY CLASSIFICATION
--------------------------------------------------------------

  Every 500 ms (WebSocket frame):
    1. SGP4 state at current time -> r_actual, v_actual
    2. RK4 state propagated from TLE epoch -> r_predicted, v_predicted
    3. delta_r = |r_actual - r_predicted|
    4. Classify by threshold -> NORMAL/WATCH/WARNING/CRITICAL
    5. Decompose delta_r into RSW components
    6. Run diagnostic engine
    7. Log to SQLite if severity >= WATCH
    8. Broadcast via WebSocket

  8d. SCENARIO INJECTOR & DEVIATED ORBIT VISUALIZATION
--------------------------------------------------------------

  How the red orbit appears:
    1. User clicks scenario button (e.g. "Orbit Raise").
    2. POST /api/satellite/{id}/simulate-event applies perturbation.
    3. app.js re-fetches GET /api/satellite/{id}/orbit (now perturbed ECEF).
    4. globe.updateDeviatedOrbit(points) plots RED dashed line on 3D globe.
    5. Original CYAN orbit remains -- compare nominal vs. deviated side by side.
    6. Click RESET -> globe.clearDeviatedOrbit() removes red line.
    7. "Deviated Orbit" layer toggle (#chkShowDeviatedOrbit) shows/hides red line.

================================================================================
  9. ORBITAL PHYSICS FORMULAS
================================================================================

  Two-body gravity:          a = -mu * r / |r|^3

  J2 perturbation (ECI):     a_J2 = (3/2) J2 * mu * R_E^2 / |r|^5
                                     * [ (5z^2/r^2 - 1) * x,
                                         (5z^2/r^2 - 1) * y,
                                         (5z^2/r^2 - 3) * z ]

  Atmospheric drag:          a_drag = -0.5 * CD * (A/m) * rho(h) * |v_rel| * v_rel
                             rho(h) = rho_0 * exp(-h / H_scale)

  Vis-viva equation:         v^2 = mu * (2/r - 1/a)

  Orbital period:            T = 2*pi * sqrt(a^3 / mu)

  GMST (IAU-76):             theta_GMST = theta_0 + omega_E * delta_t
                             theta_0 = 4.894961 + 6.300388 * T_0 (radians)
                             T_0 = Julian centuries since J2000.0

  RSW frame basis vectors:
    R-hat = r / |r|                (radial, points away from Earth)
    W-hat = (r x v) / |r x v|     (cross-track, orbit normal)
    S-hat = W-hat x R-hat          (along-track / in-track)

  10. DESIGN SYSTEM
================================================================================

  Inspired by:
    SpaceX.com: stark #000 black, pure white, electric blue, no gradients
    NASA Mission Control: amber telemetry, emerald NOMINAL, red alerts, mono fonts

  Key design decisions:
  - backdrop-filter: blur(20px) on all panels -> glassmorphism depth on black BG
  - All corners use --radius-xs (3px) for industrial precision aesthetic
  - Font: Space Grotesk (futuristic, legible) for UI; JetBrains Mono for all
    telemetry numerics (instantly readable at 2 Hz update rate)
  - Pure black panels (no gradients) maximize contrast with coloured data
  - Three.js ACESFilmic tone mapping gives globe a premium cinematic look
  - Status colours always paired with text badge (never colour alone) for
    accessibility at a glance even in peripheral vision
